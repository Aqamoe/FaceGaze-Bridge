# ADR-0012 · 界面本地化：三份文案表 + 一份很薄的查表函数

- 状态：已采纳
- 日期：2026-10-29
- 影响：新增 `ui/i18n.js`；`ui/index.html` 改为 `data-i18n` 驱动；`ui/app.js` 所有动态文案走 `t()`

## 问题

界面文案原来散在 `index.html` 与 `app.js` 里，硬编码中文。目标用户分布在中日英三个语言区
（路线图 3.13：简中 / 英 / 日），至少要能把界面切过去，而不是"只有作者看得懂"。

## 决定

### 1. 不引 i18n 库

需要的能力只有两件：**静态文案查表**、**带变量的句子**。i18next / FormatJS 自带复数规则、
RTL、日期本地化、命名空间拆分、异步加载——这些中日英都用不上（三种语言都是左到右、无复数变化），
换来的却是一个构建步骤和一个 40 KB 的运行时。项目已经明确"UI 不引构建链"，
为一个查表功能破例不划算。

所以 `ui/i18n.js` 就是三个对象字面量 + `app.js` 里 20 行的 `t(key, vars)`。

### 2. 静态文案走 HTML 属性，动态文案走 `t()`

- 静态：`<h2 data-i18n="status.fps">输入帧率</h2>`，`apply_l10n()` 统一刷一遍。
  HTML 里保留中文原文——JS 没跑起来时界面也不是空白。
- 动态（卡片、chip、pill、页面标题）：JS 生成，用 `t(key, {name})`。
- 键名按 `页面.块.项` 分层，缺键时回落到中文并 `console.warn`，
  **不静默显示 key**（key 露到界面上比缺翻译更难看）。

### 3. 语言记在 localStorage，不写引擎配置

WebView2 的用户数据目录会持久化 `localStorage`，所以"选一次，以后都是它"。
不写 `fgb.ini` 的理由：这是纯界面偏好，引擎不需要知道；写配置就得加一条 IPC 命令，
还得处理"引擎没起来时改了怎么办"。默认值取 `navigator.language`，
匹配不到就英文。

### 4. 引擎日志保持中文

日志是给排障看的，里面的措辞（"会话失败（等待初始化回复超时）"）与代码、ADR、issue 里的说法
一一对应。翻译它们会把"同一件事"变成三种说法，反而妨碍搜索。界面上已经用
`settings.lang.hint` 明说了这一点。

## 代价与遗留

- 三份文案要同步维护。缺键会告警但不会让 UI 崩；目前没有"键表校验"测试——
  想加的话，最省事的做法是在 `tools/probe_ui.py` 里把三份字典的键集合比一遍（未做）。
- 参数名、模块名、日志正文不翻译（数据，不是文案）。
- 数字/时间格式随语言走（`toLocaleString(locale_tag())`），但没有做时区与单位换算。

## 验证

`tools/probe_ui.py` 现在会：切到 en 检查首个导航项是 `Status`、切到 ja 检查是 `状態`、
确认 `localStorage.fgb.lang` 被写入，然后切回 zh；再截图核对英文界面没有溢出/截断
（卡片标题、副标题、模块页长句都过了一遍）。
