# ADR-0046 · 模块日志折叠与 engine.log 滚动

- 状态：已采纳
- 日期：2026-11-05
- 影响：`base/log_gate`（新增）、`sources/native_source`（模块日志与状态上报走闸门）、
  `ui/main`（拉起引擎前滚动 engine.log）
- 关系：配合 [ADR-0028](0028-crash-dumps-and-diagnostics.md)（诊断包整份带走 `engine.log`）、
  [ADR-0045](0045-engine-survives-a-failed-source.md)（模块是第三方代码，宿主不能被它拖垮）

## 问题

一份用户诊断包里的 `engine.log` 是 **494,262 行 / 71 MB**，其中 95% 是两条消息：

```
WARN native: Steam Link: Steam Link 上报了 6100968 条无法识别的 OSC 地址（已忽略）：/sl/xrfb/facew/ToungeTipInterdental
WARN native: Steam Link 报告错误：Steam Link 已 18446744073 秒没有数据，检查来源应用是否在发送
```

- 第一条按帧打印，计数器从 16 一路涨到 610 万（约 1000 条/秒被上游丢弃）
- 第二条是模块自己的看门狗算错了时钟（`18446744073 s ≈ 2^64 ns`，`uint64` 下溢），
  而同一段时间 `frames=435742` 说明数据一直在进——纯假告警，每 0.3 秒一条
- 该模块启用前 42 小时只有 2.3 万行；启用后 101 分钟写了 47 万行，约 **1 GB/天**
- `engine.log` 由外壳以 `FILE_APPEND_DATA` 打开，只追加不轮转；诊断包又整份拷走

模块是第三方代码，报什么日志我们左右不了；但"它报什么就原样写多少"是宿主的选择。
后果不只是磁盘：界面日志页被刷到没法看、诊断包里真问题被埋掉、用户以为引擎坏了。

## 决定

### 1. 模块日志按"类"折叠（`base/log_gate`）

`RepetitionGate`：把消息里的数字 run 抹成 `#` 作为键，同一键在 **10 s 窗口**内只落第一条，
其余只累加计数；窗口到期、状态恢复、换源时补一条

```
（同类消息又出现 3741 次，已折叠）最后一条：<原文>
```

- 抹平数字是必须的：`上报了 6100968 条`、`已 18446744073 秒` 每次都变，不抹平就认不出是同一类
- 8 个桶，交替刷两三句话的模块各自折叠；桶满时顶掉窗口起点最早的，并结清它欠下的条数
- 结算由 `poll()` 每 tick 驱动（`drain_expired`），不依赖"下一次同类消息"——
  模块一停就再也看不到还折叠了多少条
- 只折叠日志，**不改数据**：`last_error_` 照旧每帧镜像，界面显示的仍是当前错误原文

### 2. 状态上报的错误文本同样折叠

模块每帧 `report_status(ERROR, ...)` 时，界面要的"当前错误"照旧更新，但日志按类折叠，
并在 `report_status(ACTIVE)` 时把欠下的条数结清——恢复即意味着这一类结束。

### 3. `engine.log` 在拉起引擎前滚动

超过 16 MB 就滚成 `engine.log.1`（只留一份备份）。改名失败（旧引擎句柄、杀软占用）
就继续追加：写不进日志比日志太大更糟。

## 为什么不是别的方案

- **只做事后清理（截断/删除）**：用户下次照样被刷屏，等于把症状挪个地方。
- **让模块自己修**：该模块不在本仓库；而且宿主不能指望第三方模块守规矩。
- **把 WARN 降级成 DEBUG**：默认级别下就完全看不到了。折叠保留了"确实出过这件事 + 规模"。
- **改 `[stat]` 心跳间隔**：那是我们自己的低频心跳（2 s 一条），不是刷屏来源，不动。

## 验证

- `tests/test_log_gate.cpp`：键抹平数字、窗口内折叠、到期结算、`flush/reset`、
  多类并存、桶淘汰结清欠账
- `tests/test_log_gate.cpp::log_gate_folds_module_log_spam`：夹具模块
  （`tests/fixtures/log_spam_module.cpp`，每帧 8 条日志 + 1 条错误）跑 200 帧，
  即 1800 条原始日志，宿主只应落不超过 4 行
- 真机复现：同一份模块跑 1 分钟，`engine.log` 行数从 ~6000 降到个位数

## 遗留

- 窗口内被折叠掉的原文只剩最后一条，前 3740 条的细节查不到。要查细节只能临时提高
  折叠窗口（代码里 `RepetitionGate` 的构造参数）或让模块自己修日志。
- 滚动只在拉起引擎时做一次：一个连续跑很多天、日志又持续增长的会话仍会超过 16 MB。
  模块日志折叠后这条路径的增长已经很慢（每日心跳与头像切换约 6 MB），暂不加运行期检查。
