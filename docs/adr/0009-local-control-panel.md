# ADR-0009 · 本地控制面板用 HTTP + 浏览器，而不是原生窗口

- 状态：已采纳
- 日期：2026-10-29
- 影响：新增 `net/tcp_listener`、`web/json`、`web/panel`，CLI 增加 `--panel`

## 问题

到这一版为止，所有配置都只能通过命令行参数传入：换眼追模式要重启、调滤波强度要重启、
看当前绑到哪个头像只能翻日志。这样的东西只有作者自己用得下去。

## 三个选项

| 方案 | 代价 | 我的处境 |
|---|---|---|
| WinUI3 / Qt | 引一整套 UI 框架 + 构建系统 | 依赖难装，CI 也要跟着改 |
| Win32 + 自绘 | 无依赖，但消息循环、控件、DPI 缩放全是手写 | 代码量大，且**我看不到也点不了** |
| HTTP + 内嵌页面 | 一个 TCP 监听 + 一段 HTML | 零依赖，**能端到端自测** |

选了第三个。决定性理由不是"省事"，是**可验证性**：原生窗口我做不了可视化验证，
只能请人肉点一遍；HTTP 接口可以用 curl + 单测覆盖，页面本身能被脚本检查。

## 形态

```
fgb-cli run --source vrcft --panel 8787
→ http://127.0.0.1:8787/
```

只绑 `127.0.0.1`，处理一个请求就关连接，没有 keep-alive / 分块 / TLS。
这不是服务器，是本机遥控器。

### 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 内嵌单页（无框架、无 CDN、无构建） |
| GET | `/api/status` | 帧率、tick、丢弃、OSC 消息数、头像、滤波状态 |
| GET | `/api/params` | 365 个参数的当前值（按目录顺序） |
| POST | `/api/filter` | 开关滤波、改 minCutoff / beta，**立即生效** |
| POST | `/api/quit` | 优雅退出 |

### 为什么面板跑在主循环里而不是单独线程

`cmd_run` 本来就有一个 120 Hz 的手工循环。每 4 个 tick 调一次
`serve_once(0)`（非阻塞），30 Hz 的响应速度对人手足够，换来的是**零共享状态**——
不用为 Engine / Sink / Filter 加锁，也不用担心读到半个快照。

代价是单线程：一个慢请求会拖住一帧。本机回环上这个风险可以接受，
真要长期跑再拆线程也不迟（接口已经按"可在任意线程调用"设计了：
`FaceFilter` 的开关与参数是 atomic 的）。

### 滤波热更新的实现

`FaceFilter` 原本只有 `set_config()`，一改就要重建 9 个子滤波器。面板滑杆会连续发请求，
所以改成：`process()` 里比对 atomic 的 `live_min_cutoff_/live_beta_`，只在变化时才重建。
`set_enabled(false)` 直接跳过处理，重新开启时 `reset()`——否则滤波器会朝着很久以前的
状态收敛，画面会"甩"一下。

## 验证

- `curl /` → 200，5079 字节 HTML
- `curl /api/status` → 真实数据（`Eku-FT2-SD`、45 参数、156 目标、滤波状态）
- `curl /api/params` → 365 项
- `POST /api/filter {"enabled":true,"min_cutoff":2.5,"beta":0.8}` → 再查 status 确认生效
- 未知路径 → 404；页面 JS 用 `node --check` 过了语法
- 74 个单元测试（新增 7 个覆盖 JSON 转义与 HTTP 解析）

## 遗留

- **没有认证**。只绑回环，但同机其他程序可以调用。本地工具暂时接受这个风险
- 页面 500 ms 轮询，没有 WebSocket。回环上无所谓，代码少一半
- 还不能在面板里改输出目标 / 参数集 / 校准档案——这些仍要重启
- 没有托盘常驻，要自己开着控制台窗口

## 下一步

托盘壳（Win32 消息循环 + 图标菜单）作为包装层，把"启动/停止/打开面板"收进右键菜单。
那层做不了自动化验证，需要人点几下确认。
