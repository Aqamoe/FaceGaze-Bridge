# ADR-0016 · 单入口桌面应用：窗口拉起引擎，关窗即停

> **后续**：关窗语义已由 [ADR-0022](0022-tray-shell-and-close-semantics.md) 修订——
> 现在"关闭窗口 = 收进托盘，追踪继续；托盘「退出」才停引擎"。本文其余决定
> （单入口、Job 生命周期、端口扫描、默认 VRCFT 输入源）不变。

- 状态：已采纳（对打包发行版取代 [ADR-0010](0010-webview2-ui-and-websocket-ipc.md) 里"界面可单独关闭、
  引擎继续跑"的使用方式；关窗语义见 ADR-0022）
- 日期：2026-10-29
- 影响：`src/ui/main.cpp`、`fgb-ui` 输出名改为 `FaceGaze Bridge.exe`、`packaging/`（新增 `icon.ico` /
  `app.rc.in`，删除两个 `.cmd`）、install 规则、`launch_ui` 查找的名字、`--panel` 启动失败改为致命

## 问题

ADR-0010 把进程拆成"引擎 + 外壳"，命令行形态是：

```
fgb-cli run --source vrcft --ui
fgb-cli run --source vmc   --ui
```

为了不重写命令行，发布包里放了两个 `.cmd` 让用户双击。实际交给真机用户后暴露出三个问题：

1. **入口像是脚本工具，不像软件。** 目录里两个 `.cmd`、一个黑窗口、一个界面窗口，
   用户要先判断"我该点哪个"，关掉黑窗口又会悄悄停掉追踪。
2. **引擎必须带参数才能起。** 直接双击 `fgb-cli.exe` 只会打印用法；双击 `fgb-ui.exe`
   又只有界面没有数据——两个 exe 单独都"不完整"。
3. **用户看不到失败原因。** 模块缺失、VRCFT 没关、端口被占，都写在黑窗口里；
   先关黑窗口再问"为什么不动"，日志已经没了。

## 决定

### 1. 唯一入口是 `FaceGaze Bridge.exe`

`fgb-ui` 从"纯外壳"升级成**桌面入口**，仍然不含业务逻辑：

- 启动时 GET `http://127.0.0.1:8787/healthz`：
  - 返回自家引擎的 `{"ok":true,...}` → 只连，不动它（命令行起的引擎、第二次双击都走这条路）
  - 连不上 → 隐藏启动同目录的 `fgb-cli.exe run --source vrcft --panel 8787`
- 认不出的命令行参数原样转给引擎（`--source vmc`、`--vmc-out`、`--vrchat` …），
  外壳不需要理解引擎的全部选项
- 引擎 stdout/stderr 重定向到 `%LOCALAPPDATA%\FaceGazeBridge\engine.log`（追加写），
  界面「设置」页直接显示这个路径
- 控制面端口从 8787 起扫 10 个：先找已有引擎（可附着），再找空闲端口（可新建）。
  8787 被别的程序占用时自动用 8788/8789…，界面地址跟着变

文件名用产品名（含空格）由 `OUTPUT_NAME` 决定；CMake 目标仍叫 `fgb-ui`，探针/文档按目标名引用。
引擎保持 `fgb-cli.exe`：它是命令行工具，也是外壳调用的对象，不面向普通用户。

### 2. 生命周期用 Job 对象绑定

外壳创建 `CreateJobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，把**自己拉起的**引擎放进去。
外壳正常关闭、崩溃、被任务管理器结束，句柄一关引擎（及其模块子进程）跟着结束：

- 关闭窗口 = 停止追踪（**已被 ADR-0022 修订为"收进托盘"**）。这是普通桌面软件的预期，
  也避免"界面没了但输出还在发"的黑盒状态；引入托盘后这条改用托盘菜单的「退出」表达
- `restart_engine`（退出码 3）时外壳只重新拉起引擎，**不重新导航**：页面保持原样，
  WebSocket 自己重连；避免重启时白屏/丢页面
- 别人起的引擎没有句柄关系，外壳退出不会误杀它（命令行/自动化排查时依然可以"关界面不停追踪"）
- 不采用"界面退出时发 IPC quit"：那要求外壳理解协议，而 ADR-0010 的边界就是外壳里没有协议逻辑

### 3. 默认输入源是 VRCFT 模块；失败时给一次 VMC 机会

产品默认 `--source vrcft`。引擎在启动阶段就挑模块，没装模块会立刻退出（退出码 2）。
外壳的看门狗发现"还没连上引擎就退出了"，弹窗给出日志路径，并允许一键改用
`--source vmc` 重试——不需要用户再去找另一个 `.cmd`。

固定默认而不是"自动探测"，是因为自动探测会在"模块装了但硬件没连"时静默换成 VMC，
用户看到的数据来源和预期不一致。失败要**明说**。

### 4. `--panel` 起不来就是致命错误

之前控制面监听失败只打印一行，引擎继续跑——在没有外壳的场景下等于变成没人能停的后台进程。
现在显式要了 `--panel`（包括 `--ui` 隐含的）却监听失败，直接退出，让**启动入口**去报错。

### 5. 窗口尺寸按 DIP 给

默认 1360×860、最小 1100×700（逻辑像素），创建时按显示器 DPI 放大后再夹到工作区内。
旧版固定 1180×780 **物理像素**：125%/150% 缩放下只有 ~940×620 DIP，参数热力图和模块卡片会被挤成两列。
窗口头同时设置深色标题栏（`DWMWA_USE_IMMERSIVE_DARK_MODE`，老系统失败就保持系统配色）和图标资源。

### 6. 图标与版本信息走 Windows 资源

`packaging/icon.ico` 是多尺寸（16–256）PNG 压缩 ICO，由 `packaging/app.rc.in` 引用；
`configure_file` 把 `project(VERSION)` 写进 VERSIONINFO（ProductName / FileDescription 都是
`FaceGaze Bridge`）。`fgb-ui` 与 `fgb-cli` 共用这套资源，任务栏、资源管理器、
文件属性里看到的都是同一个图标和名字。

## 代价

- 从命令行 `fgb-cli run --source vrcft --ui` 启动时，界面关掉引擎仍在跑（外壳没有 job 成员）。
  这是保留的排障形态，不是发版路径；README 与 `packaging/README.txt` 说清了两种情况的区别。
- 引擎日志不再显示在控制台窗口里，现场排障依赖 `engine.log` 与界面日志页。
  好处是"先关窗口再看日志"的丢日志问题消失了。

## 验证

- `cmake --install` 后双击 `dist/FaceGaze Bridge.exe`：窗口出现、页面连上、图标为项目图标
- `"FaceGaze Bridge.exe" --debug-port 9222` + `python tools/probe_ui.py 9222 8787` 断言页面渲染
- 托盘「退出」后，任务管理器里没有残留的 `fgb-cli.exe` / `msedgewebview2.exe`
  （关闭窗口只是收进托盘，引擎继续跑，见 ADR-0022）
- 无模块环境：弹窗出现，选"是"后以 VMC 启动并连上
