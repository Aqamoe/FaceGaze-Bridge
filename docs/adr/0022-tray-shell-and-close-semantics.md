# ADR-0022 · 托盘常驻外壳与关窗语义

- 状态：**已实施**（2026-10-29）
- 日期：2026-10-29
- 修订：[ADR-0016](0016-single-entry-desktop-app.md) §2 的"关闭窗口 = 停止追踪"
- 前置关系：[ADR-0020](0020-steamvr-autostart.md) 的 SteamVR 自启动必须等这一步完成
- 影响：`src/ui/main.cpp`（托盘、`--tray`、单实例、关窗分支）、`src/web/ipc.cpp`
  （新增 `/api/quit`、`/api/restart`，供外壳控制引擎）、`packaging/README.txt`、
  `docs/03-roadmap.md`、`docs/02-features.md`、`README.md`

## 问题

SteamVR 自启动要求 FGB"跟着起来但不打扰"：不能每次戴头显都弹一个窗口，也不能靠
"最小化到任务栏"冒充后台驻留。同时，用户对窗口右上角那个 × 有固定预期，而这个项目
原来的语义是"关窗即停引擎"（[ADR-0016](0016-single-entry-desktop-app.md)）：

| 做法 | 用户实际看到 | 问题 |
|---|---|---|
| × 直接停引擎退出 | 关窗后追踪中断 | 自启动场景里用户只想关掉界面，不想停追踪 |
| × 最小化到任务栏 | 任务栏多一个不知道干什么的窗口 | 看起来像没关掉 |
| × 收进托盘（采纳） | 任务栏干净，托盘有图标，追踪继续 | 需要文档说清"退出"在哪 |

## 决定

### 1. 托盘图标常驻，两种启动方式都有

`FaceGaze Bridge.exe` 无论带不带 `--tray` 都创建托盘图标。菜单项（按系统 UI 语言
显示中文 / 英文 / 日文）：

| 菜单项 | 行为 |
|---|---|
| 显示窗口 | 窗口从托盘回到前台；WebView2 与页面按需创建 |
| 启动引擎 / 停止引擎 | 同一位置切换：引擎在跑就给"停止"，没跑就给"启动" |
| 重启引擎 | 引擎活着时可用；引擎以退出码 3 结束，外壳原地拉起（与界面里的"重启引擎"同一路径） |
| 退出 | 停引擎并退出进程（Job 对象一并结束模块子进程） |

单击托盘图标等同于「显示窗口」；右键（或 `WM_CONTEXTMENU`）弹菜单。菜单状态来自
真实引擎状态（外壳自己拉起的看进程句柄，别人起的每秒 `/healthz` 探测），
不是"点了就假设成功"。

### 2. 关窗 = 收进托盘；托盘「退出」才停引擎

- `WM_CLOSE` 在**没有**托盘图标或 `quitting` 为真时才销毁窗口；否则 `SW_HIDE`，
  引擎与追踪继续。
- 第一次收进托盘弹一次气泡："仍在托盘运行，右键图标可以退出"。这条提示是
  [docs/04-engineering.md](../04-engineering.md) R16 风险（用户以为追踪停了）的缓解。
- `WM_QUERYENDSESSION` / `WM_ENDSESSION` 允许系统关机时正常退出。
- 资源管理器重启后托盘图标会消失（`Shell_NotifyIcon` 的经典问题）：收到系统的
  `TaskbarCreated` 广播就重新加一次。

### 3. `--tray`：不弹窗口，也不预先创建 WebView2

`--tray` 让外壳：

- 窗口创建后保持隐藏（消息循环、托盘、引擎照常）
- **不**创建 WebView2 环境；第一次「显示窗口」时才创建。理由：自启动场景用户可能
  整晚不开界面，没必要先养两个 `msedgewebview2.exe` 进程（实测冷启动后进程数 0）。
- `--tray` 是外壳自己的参数，不转发给引擎（转发过去会被当成未知参数，退出码 2）。

SteamVR 的 `app.vrmanifest` 里 `arguments` 用 `--tray`（见 ADR-0020 §5）。

### 4. 单实例：命名互斥体 + 注册消息广播

- 互斥体 `Local\FaceGazeBridge.Shell`：第二个实例发现已存在就不启动。
- 第二个实例用 `PostMessageW(HWND_BROADCAST, 注册消息, 0, 0)` 通知已有实例把窗口
  带到前台，然后自己退出。已有实例的窗口即使藏在托盘也能被叫出来。
- **不用 `FindWindow`**：本机实测（Win10 22H2）从另一个进程 `FindWindowW` 找不到
  自家隐藏窗口（`EnumWindows` 能看到，`FindWindowW` 返回 0 且 `GetLastError()==0`）。
  与其猜系统行为，不如用广播——它本来就不需要知道对方的 HWND。
- 例外：带 `--debug-port`、`--url` 或 `--port` 的实例不参与单实例检查，允许多开。
  - 探针必须能单独起一个测试实例（`AGENT.md` §3.4 要求单独的 `--user-data`），
    否则 CDP 端口不会监听
  - `fgb-cli run --ui` 是用 `--port <端口>` 拉起外壳的；被已有窗口顶掉会让它
    连到另一个引擎上，所以显式 `--port` 也视为"多开"

### 5. 外壳怎么让引擎停下/重启：两个本机 HTTP 端点，不实现 WebSocket 客户端

ADR-0016 §2 明确"外壳里没有协议逻辑"。托盘菜单需要停止/重启引擎，两种做法：

| 方案 | 代价 | 结论 |
|---|---|---|
| 外壳实现最小 WebSocket 客户端 | 约 200 行（握手、掩码、base64/sha1），且要维护连接状态 | 不采纳 |
| 直接 `TerminateProcess` | 不是优雅退出；模块进程靠 Job 兜底，但日志/共享内存收尾会缺 | 不采纳 |
| `POST /api/quit`、`POST /api/restart` | 控制面本来就同时提供 HTTP；外壳只需一个"发一行动作然后退出" | **采纳** |

两个端点只绑 `127.0.0.1`，GET/POST 都接受（`curl` 排障方便）。它们只置位引擎已有的
`quit` / `restart_engine` 原子量，语义与界面的「停止引擎」「重启引擎」完全一致。

### 6. 托盘模式下的失败策略：不弹模态框，但也不静默

`--tray` 启动时用户可能不在电脑前，弹出"是否改用 VMC 重试"是个坏体验；但静默失败
同样不可接受。展开为：

1. 引擎在 3 秒内以非 0 退出（典型：没装模块、运行时缺失）→ 自动按 ADR-0016 §3 的
   老逻辑切一次 VMC，并用**气泡**说明"没有可用的 VRCFT 模块，已改用 VMC 输入重试"。
2. 仍失败 → 外壳留在托盘，气泡提示"引擎启动失败，右键查看日志或重试"，`engine.log`
   里有具体原因；托盘菜单显示「启动引擎」供重试。
3. 用户主动停止（托盘「停止引擎」、界面「停止引擎」、或引擎已经正常跑了 3 秒以上再
   退出）→ 只提示"引擎已停止"，**不**报"启动失败"。
4. 窗口形态（非 `--tray`）保持原行为：弹窗 + 一键切 VMC。

## 代价与风险

- **关窗不再停追踪**：这是本 ADR 最需要被文档覆盖的一条。`packaging/README.txt`、
  `README.md`、界面输出页的说明、第一次收进托盘的气泡都会写明"托盘退出才停引擎"。
  需要"关窗即停"的用户可以：托盘「退出」，或在界面设置页点「停止引擎」。
- **托盘图标是新的失败面**：`Shell_NotifyIcon` 失败会让关窗变成直接退出（代码里
  `tray_icon` 为假时 `WM_CLOSE` 走销毁分支，不会留下点不到的进程）。
- **托盘文案不进 `ui/i18n.js`**：外壳是原生窗口，拿不到页面的 `localStorage` 语言
  选择，所以按系统 UI 语言选一份内置文案。代价是"页面里选了英文、托盘还是中文"，
  可接受；要统一得让页面把语言写进引擎配置再回传给外壳，超出本步范围。
- **多显示器/DPI**：托盘图标按 `SM_CXSMICON` 取尺寸，避免 150% 缩放下发糊。

## 验证（2026-10-29 实测，Windows 10 22H2）

- [x] `"FaceGaze Bridge.exe" --tray --source replay ...`：窗口不可见、外壳存活、
      引擎在跑、`msedgewebview2` 进程数 0
- [x] 同一命令行再启动一次：第二个实例退出，第一个实例的窗口变为可见
- [x] 对窗口 `WM_CLOSE`：窗口不可见、外壳存活、引擎继续输出
- [x] 真实托盘菜单（右键 → 键盘 ↓↓ Enter）：引擎停止、外壳留在托盘、窗口仍隐藏
- [x] 真实托盘菜单「重启引擎」：引擎退出码 3 → 外壳原地拉起，日志出现新的"引擎启动"
- [x] 真实托盘菜单「退出」：外壳退出，Job 带走引擎，无 `fgb-cli.exe` /
      `FaceGaze Bridge.exe` 残留
- [x] `POST /api/quit` / `POST /api/restart` 单独验证（curl 等价物）
- [x] 停止后日志里不再出现"引擎启动失败（退出码 0）"这类误报
