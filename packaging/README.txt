FaceGaze Bridge —— 绿色版
============================================================

怎么用
------
双击下面两个之一（Windows 会弹一个黑窗口 = 引擎日志，再弹一个界面窗口）：

  启动 (VRCFT 模块).cmd   用 VRCFT 的模块（PICO / Quest / 其他）当输入
  启动 (VMC).cmd          用 VMC 协议当输入（VSeeFace 等）

第一次运行前确认：
  1. VRChat 已启动，并在设置里打开了 OSC（默认发到 127.0.0.1:9000）
  2. 用 VRCFT 模块时：VRCFT 本体必须完全退出（模块的沙箱端口是独占的）
  3. 系统里有 WebView2 Runtime。Win10/11 随 Edge 预装；没有的话装
     "Microsoft Edge WebView2 Runtime"（Evergreen）即可

界面里能做什么
--------------
  状态：帧率 / 累计帧 / tick 抖动 / OSC 条数 / 当前头像
  模块：扫描磁盘上的 VRCFT 模块，选启动时加载哪个，故障时显示模块自己报的原因
  参数：365 个参数的热力图（只显示已绑定的），搜索过滤
  输出：参数集 / 眼追模式 / 绑定条数，重新读取头像参数表
  日志：引擎与模块日志，可过滤级别
  设置：One Euro 滤波开关与滑杆，日志级别，停止引擎

进阶：同时输出给别的程序
------------------------
两个 .cmd 都会把多余参数原样传给引擎。想让同一张脸既驱动 VRChat 又驱动
Unity 场景 / VSeeFace，用命令行补一个 VMC 输出目标（端口别和接收端冲突）：

    "启动 (VMC).cmd" --vmc-out 127.0.0.1:9100

之后的输出会同时走 VRChat OSC（9000）与 VMC（9100）。界面"输出"页能看到发了多少条。

文件说明
--------
  fgb-cli.exe   引擎（控制台程序，被上面两个 .cmd 调用）
  fgb-ui.exe    界面外壳（WebView2 窗口，可以单独启动，会自动重连）
  ui\           页面资源。改界面不用重编，替换这里的文件刷新即可
  fgb.ini 等配置在 %APPDATA%\FaceGazeBridge\fgb.ini

常见问题
--------
  界面一直"等待引擎…"
     引擎没起来或端口被占。看黑窗口里的报错；确认没有第二个 fgb-cli 在跑。

  模块页显示"故障"
     卡片里就是模块自己报的原因。最常见的是端口被占（还在跑 VRCFT），
     或者头显/串流软件没连上。修好后点"重新扫描"，或重启引擎。

  VRChat 里表情不动
     先看界面状态页的"命中参数"是不是 0：
     是 0 → 头像参数表没读到，去"输出"页点"重新读取头像参数表"；
     不是 0 → 检查 VRChat OSC 端口、以及模型是否绑了 FT/v2 参数。

  关掉界面后追踪还在继续吗
     在。界面只是看板，关掉不影响输出；要停引擎就关那个黑窗口或按 Ctrl+C。

日志与配置
----------
  控制面地址：http://127.0.0.1:8787/（浏览器也能打开，方便对照）
  配置：%APPDATA%\FaceGazeBridge\fgb.ini
